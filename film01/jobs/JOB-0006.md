# JOB-0006
类型: image + video_plan + video_submit + video_fetch
分支: main
目的: 重画 S05 尾帧（不花钱）；在本地重算报价（不花钱）；对用户已签批准单的镜头提交 Seedance 并下载抽帧（**花钱**）。

开工前先运行 `python film01/tools/selfcheck.py`，把输出贴进报告。如果 ARK_API_KEY 或 ffmpeg 显示缺少，A、B 两部分照做，C 部分不做。

## A. 重画 S05 尾帧（不花钱，只画一次）
| 输出名 | 提示词文件 | 参考图（按这个顺序传入） |
|---|---|---|
| S05_last | `film01/prompts/S05_last_v3.txt` | `film01/images/S05_first_v1.png`、`film01/images/S05_last_v2.png`、`film01/images/CHAR_fish_sheet_v1.png` |

1. `python film01/tools/collect_image.py --stamp`
2. 按提示词原文生成，三张参考图都要实际传入
3. `python film01/tools/collect_image.py --name S05_last --since <数字> --prompt film01/prompts/S05_last_v3.txt --refs film01/images/S05_first_v1.png film01/images/S05_last_v2.png film01/images/CHAR_fish_sheet_v1.png --job JOB-0006`，应归档为 `images/S05_last_v3.png`
4. `python film01/tools/fit_ratio.py images/S05_last_v3.png`

报告里写明：和 S05_first_v1 比，背景有哪些地方不一样（书架上的东西、台灯、绿植、窗户、地上的人影、门口的暖光）；袜子长度；腿的比例；裙子有没有盖住膝盖；尾巴在画面哪一侧。

## B. 本地报价（不花钱）
依次运行（在仓库根目录）：
```
python film01/tools/seedance.py plan shots/S01_v1.json
python film01/tools/seedance.py plan shots/S02_v2.json
python film01/tools/seedance.py plan shots/S04_v2.json
python film01/tools/seedance.py plan shots/S06_v1.json
python film01/tools/seedance.py plan shots/S05_v2.json
```
前四个导演已经在云端算过，正常情况下会显示“已存在，输入没变”，这一步用来确认 Windows 和云端算出的结果一致。如果显示“输入变了”，**停止 C 部分**，在报告里写明。
第五个（S05_v2）会生成新的报价单。**本工单不提交 S05_v2**，它要先由导演审过新的尾帧。

## C. 提交视频（花钱，只提交用户已签批准单的镜头）
只处理 `film01/approvals/` 下存在批准单的这几个镜头：S01_v1、S02_v2、S04_v2、S06_v1。没有批准单的跳过，在报告里写“等待用户批准”。**不要提交 S05_v1 或 S05_v2。**
提交这一步需要联网，沙箱要求提升权限时，告诉用户“这一步会花钱提交 <clip>”。

### C1. 先单独试 S01_v1
```
python film01/tools/seedance.py submit shots/S01_v1.json
python film01/tools/seedance.py poll S01_v1 --wait 15
python film01/tools/inspect_video.py S01_v1
```
继续往下之前，必须同时满足：poll 显示 succeeded；`video_check/S01_v1/summary.json` 里时长在 3.8～4.3 秒之间、高度是 480。任何一条不满足，就停下，后面的镜头都不提交，把完整输出写进报告。

### C2. 其余三个
S01_v1 通过上面的检查后，对 S02_v2、S04_v2、S06_v1 依次运行 `submit`，三个都提交后，再逐个运行 `poll <clip> --wait 15` 和 `inspect_video.py <clip>`。

任何一步失败都不重试，也不换参数。退出码 3（疑似欠费）表示立即全部停止。

## 报告里写明
- A：上面列的各项观察
- B：五条 plan 命令的完整输出
- C：每个镜头的 task_id、最终状态、`logs/api/<clip>.json` 里的 usage（token 数）、`video_check/<clip>/summary.md` 的内容
- 你看到的视频情况。只写客观事实，例如“第 2 秒人物的脸变形”“尾巴出现两条”“背景闪烁”。你看过视频，导演看不到
